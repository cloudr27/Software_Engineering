# Software_Engineering
## Добро пожаловать в проект! 
Этот репозиторий создан в рамках лабораторной работы по программной инженерии.

## Правило работы с кодом

В проекте используется базовая модель ветвления:
*   **`main`** — стабильная ветка. Здесь лежит только рабочий код. **Прямой пуш в `main` запрещен!**
*   **`dev`** — основная ветка для разработки. Сюда сливаются готовые фичи перед релизом.
*   **Feature-ветки** — для каждой новой задачи (Issue) создается отдельная ветка от `dev` (например, `feature/auth` или `fix/login-bug`).

**Процесс внесения изменений:**
1.  Создайте ветку от `dev` для своей задачи.
2.  Внесите изменения и сделайте коммит.
3.  Создайте Pull Request (PR) из вашей ветки в `dev`.
4.  PR должен получить **approve** от тимлида (или другого участника команды) перед мержем. 
5.  **Это правило касается всех, включая тимлида** — никто не пушит в `main` или `dev` напрямую без PR.

## О проекте
**Тема:** Система поддержки бизнес-процессов IT (на основе практик ITIL).

Мы разрабатываем учебный прототип **Service Desk** (портала поддержки пользователей). 
Основная цель проекта — автоматизировать процесс обработки инцидентов и запросов на обслуживание, чтобы IT-отдел мог работать по стандартам ITIL. 

### Ключевые функции (MVP):
*   Создание и регистрация заявок (инцидентов) пользователями.
*   Приоритизация задач (SLA - Service Level Agreement) и назначение исполнителей.
*   Отслеживание жизненного цикла заявки (от «Открыта» до «Закрыта»).
*   База знаний (Wiki) с типовыми решениями проблем.

### Используемый стек технологий (планируемый):
*   **Frontend:** React (или HTML/CSS/JS)
*   **Backend:** Python (FastAPI)
*   **База данных:** PostgreSQL
*   **Инструменты:** GitHub (Issues, Wiki, Actions для CI/CD)

## Как мы работаем (Процесс)
Мы используем гибкую методологию разработки (Agile). Все задачи фиксируются во вкладке **Issues**. 
*   Задачи распределяются по приоритетам (P1 - срочные, P2 - средние, P3 - плановые).
*   CI/CD настроен через **GitHub Actions** для автоматической проверки кода.
